## Precise engineering blockers

* `FormalLogJet` retains `open PiExponent.FormalJetDerivatives` at source line
  10, authoritative byte range 274--310. Its uniquely identified owner is
  `Jets.FormalJetDerivatives`; that Def bundle exists with three selected units
  and imports `JetGeometry`, but it is absent from FormalLogJet's planned Def
  imports. The current generator therefore rejects it. Resolve this as an
  explicit syntax-context dependency (or prove an exact AST open-command
  removal safe); do not treat the namespace spelling as evidence of availability.
* `shiftMap.eq_1` is an actual source equation theorem obtained through Lean's
  equation API. The original provenance probe passed, but the generated
  `DefFormalLogTruncation` side still needs actual equation API output and
  structural type/full-primary-definition-value correspondence. Only then can
  `shiftEquiv_apply := rfl` be recognized as available in the generated module.
  No `eq_1` prefix/suffix inference is sufficient.
* `Parameters` and `AdmissibleParameters` retain whole structure commands.
  Their command owner graph includes inductive/constructor/recursor/definition
  and theorem accessors. The current ordinary-only validator and fast resolver
  explicitly refuse these cases. Supporting atomic structure CI domains and
  exact `kindMetadata`/constructor/recursor comparison is required before this
  chain can use the new fast pipeline. This is a verification-interface gap,
  not an unverified source proof.
* The three public source theorem overrides (`exists_admissible_parameters`,
  `actual_minor_arithmetic_lower_bound`, `tendsto_collisionRate`) still have
  `lean_or_type_validated=false`. Their `_source017` binding/ref edits and exact
  generated type comparison remain necessary for the contradiction chain.
  The historical 97 clashes were internal planned duplicate globals, **not**
  97 live platform-name collisions.
* Twelve planned nodes still have private inline helpers. The selected plan
  has 124 private/deprivate Definition units, including 116 deprivate units.
  Cech's `higherCochainAddCommGroup` exact command and copied-prefix actual CI
  provenance is now certified source-side; generated-alias availability remains
  false. Keeping source context removes unnecessary reconstruction, but does
  not establish generated private kernel-name/type/value correspondence.

This audit does not claim these are all generator rejection paths: the saved
Main preview report is from the earlier plan and stops at its first FormalLog
error. It must not be presented as a fresh exhaustive 875-plan node-generation
result.

## Original module closure and batching

Main's exact original source import closure has **873 modules**, 4,439,786
bytes and 95,393 lines. The copied 875-tree's two modules outside that closure
are `Approximation.AdmissibleDeterminantSequences` and
`Approximation.DeterminantSequences`. Only three original files exceed the
advisory 500-line size; the largest is FiniteCoverCohomology (1,248 lines,
58,349 bytes). Recorded source Stage2 preflights in the Main closure peak at
147.653 seconds. These are source witnesses, not generated module certificates.

Bulk snapshots can reduce repeated process/import overhead without changing
the decomposition: compile providers in DAG order; then group only providers
with actual stable certified OLeans into an isolated public snapshot importing
those exact modules. Keep each request's module owner, graph row and kind
binding; compare its generated structural CI against authenticated source
rows; record all imported OLean hashes and each output shard/log. A first
meaningful candidate group is the 23 requests from PolynomialFrameDegree,
SimplexFloor and SimplexUnweighted. Each group still needs its own bounded
preflight; no group runtime estimate is a validation result. Private/structure
requests remain ineligible until their explicit interface support is complete.

The 174-row source subset has an actual 30.936-second certificate. Its coverage
is selected provider rows, not all 873 source modules or all 683 Def interfaces.
Do not substitute it for missing source requests in a newly generated provider.

## Whole-proof Definitions alternative

No whole-library Def upload is proposed. `references/contribute.md` line 135
says to avoid complex/multi-step theorem proofs in Definitions; line 165 directs
supporting lemmas to separate theorem submissions. `upload_full_project.md`
describes theorem nodes as first-class and embeds theorems only where a def body
needs them. Existing embedded-theorem Def publications establish those concrete
cases, not permission or verified backend behavior for a complete DefMain proof
library. Retaining the original source module skeleton for selected Def material
and necessary small shared helpers is already the applicable normal-playbook
method; the 224 proof nodes remain the target decomposition.

The documented general compile limit is 300 seconds and ~500 lines is advisory.
The local API references do not state a maximum definition-body byte size, so
this audit makes no claim that the largest original module would be accepted
as a new definition. No Lean/API call or frozen implementation/input edit was
performed.
