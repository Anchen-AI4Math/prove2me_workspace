# 本工作区：定理依赖图交付

本地约定：求解任务的交付包括证明正确性与定理关系组织。仅获得
`ACCEPTED`，或仅让主目标变成 `Proved`，不足以说明预期的 graph 已整理。
这一约定用于组织与复用，不改变平台判定任务完成的规则，也不扩大用户授权范围。

## 从陈述规划关系

- 先读当前任务的主目标 graph、里程碑及已有 decompositions，确认现有声明、环境、
  定理 ID 和已有归约。不要把里程碑的排列顺序当作证明依赖。
- 按证明内容辨认可复用的核心引理：多个目标共用的工具、主结论的实质性组成部分、
  或能被后续证明独立调用的中间结果。优先使用平台已有声明。
- 需要新子定理时，保持与来源和原陈述一致，写清假设与自然语言含义，按
  [contribute.md](contribute.md) 发布。保留原目标与平台定义，不用同义复制替代它们。
- 对彼此独立的结论，记录各自的根及自然依赖。只有来源和任务范围支持一个整体
  结论时才组织相应汇总定理；不要为了图的外观强行制造主目标的前置条件。

## 让关系进入平台

平台 graph 的证明关系来自经验证的归约，不能靠本地 Markdown 画线、解释文字或
单独的直接证明提交代替。

1. 按 [prove.md](prove.md) 在父目标的证明中导入真实使用的子声明，例如
   `Theorems.Thm_Namespace_lemma`，并调用它的原始 Lean 名称。避免重新写已经证明的
   公共引理。全部子项已证明时，归约仍需提交，服务端 `ACCEPTED` 后才有相应记录。
2. 先在本地核对父目标的精确类型，再向 `/verify` 提交。不要导入父目标自身，
   不要用无关导入、未被使用的结论或循环证明制造依赖边。
3. 本地 `Theorems/` 原始参考文件中的 `by sorry` 不是已证明的实现。使用接受证明的
   独立镜像或证书核实本地闭合性，并保留原始参考文件；不要把导入占位符后编译成功
   报成无未证明依赖的验证成功。
4. 轮询归约结果。区分 `ACCEPTED` 与仍有开放子项的 `SKETCH_ACCEPTED`，不能把后者
   报成整条证明已闭合。已经直接证明的父目标也可以补交有实际复用价值的归约，
   原接受证明和精确陈述继续保留。

## 完成前核对实际 graph

使用当前服务端响应，按 [missions.md](missions.md) 与 [prove.md](prove.md) 查询：

```text
GET /theorems/MAIN_THEOREM_ID/graph
GET /theorems/PARENT_THEOREM_ID/decompositions
GET /theorems/MILESTONE_THEOREM_ID/graph
```

- 核对预期的子声明是否成为节点、归约是否列出了这些子声明，以及图中是否出现
  相应依赖边。节点存在、声明已发布或父目标 `Proved` 均不能单独证明连接成功。
- 以响应实际采用的方向和字段检查边；记录定理/定义节点 ID、父子关系、归约提交
  ID、判定及读取时间，不凭本地 import 列表推测线上结果。
  平台可能把关系表示为“子定理 → 归约提交节点 → 父定理”，此时应核对完整路径，
  不要误以为只有子定理与父定理之间的一条直接边才算连接成功。
- 图接口若分页、截断或标记未展开邻接项，读取所需子图后再判断覆盖范围。
  无访问权限或外部故障时保留已完成证明，明确列出尚未核实的连接。
- 将图响应和核对摘要保存到本任务 `verification/`。更新任务交接中的依赖图说明，
  包括独立根、已连接分支及仍未接入的项，方便后续继续使用。

完成报告分别说明证明通过情况与 graph 验证情况。若目标确实是基础叶结论且没有
适合拆出的可复用引理，可保留叶节点并解释原因；不要为满足节点数量创建新定理。
